# 运维、备份、迁移、安全与许可证

[返回总目录](00_总目录与实施路线.md)

> 本文是教育 AI 扩展的联合运维补充。LMS 的 MongoDB 逻辑备份、私有媒体卷、极空间
> SMB 挂载、Restic 加密仓库和恢复演练，以
> [本地 Ubuntu 部署指南第 7.4 节](../deployment/local-ubuntu-deployment.md#74-数据备份)
> 为准。不要用直接复制运行中 MongoDB 数据卷的方式替代 `mongodump --oplog`。

## 1. 日常运维

LMS 和教育 AI 扩展是两个独立部署单元。日常先确认 LMS 正常，再按需启动 DeepTutor：

```bash
# LMS
cd ~/LMS
docker compose -f docker-compose.ubuntu.yml ps

# 教育 AI 扩展
cd /srv/edu-stack
docker compose up -d
```

状态：

```bash
docker compose ps
docker stats --no-stream
free -h
df -h /srv
```

日志：

```bash
docker compose logs --tail=200 deeptutor
docker compose logs -f deeptutor
```

8 GB 机器建议在不生成教学内容时停止 DeepTutor 以释放内存，LMS 继续运行：

```bash
cd /srv/edu-stack
docker compose stop deeptutor
```

重启：

```bash
docker compose restart deeptutor
```

拉取镜像：

```bash
docker compose pull
```

不要把 `pull` 直接等同于升级。只有备份完成、明确 tag/digest、变更说明已阅读并有回滚
窗口时才重建容器。

## 2. 资源监控

### 2.1 内存

```bash
free -h
swapon --show
zramctl
docker stats --no-stream
```

需要关注：

- available 是否长期低于 500 MB；
- swap 是否持续快速增长；
- DeepTutor 是否接近 3 GB；
- 是否发生 OOM。

当 LMS 和 DeepTutor 同时运行时，建议把告警线提高到 `MemAvailable < 1 GB`。连续
触线时先停止 DeepTutor、K12 抽取和索引任务；不要靠无限增加 swap 维持正式学习服务。

检查 OOM：

```bash
journalctl -k --since "24 hours ago" | grep -i -E 'oom|killed process'
```

### 2.2 磁盘

```bash
df -h
du -sh /srv/edu-stack/*
docker system df
```

不要频繁执行：

```bash
docker system prune -a
```

该命令可能删除后续需要的镜像和缓存。清理前应逐项确认。

### 2.3 SSD

```bash
sudo smartctl -a /dev/sda
```

建议每月检查一次，并确保重要数据有外部备份。

### 2.4 温度

```bash
sudo apt install -y lm-sensors
sudo sensors-detect
sensors
```

老笔记本长时间执行 MinerU 时应注意散热、风扇和灰尘。

## 3. Docker 日志轮转

创建或修改：

```bash
sudoedit /etc/docker/daemon.json
```

推荐：

```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "20m",
    "max-file": "3"
  }
}
```

应用：

```bash
sudo systemctl restart docker
cd /srv/edu-stack
docker compose up -d
```

如果现有 `daemon.json` 已有配置，应合并 JSON，而不是覆盖。

## 4. 更新策略

### 4.1 Ubuntu

```bash
sudo apt update
sudo apt upgrade
```

大版本或内核更新前：

- 检查磁盘；
- 完成备份；
- 确认可以 SSH 登录；
- 确认有本地物理访问方式。

### 4.2 DeepTutor

不要在没有备份的情况下更新，也不使用浮动 `latest` 作为长期配置。

```bash
# 先执行第 6 节联合 Restic snapshot，并记录 snapshot ID
cd /srv/edu-stack
docker compose stop deeptutor
docker compose pull
docker compose up -d
docker compose logs --tail=200 deeptutor
```

验证：

- 页面；
- 模型设置；
- embedding；
- 知识库；
- 会话；
- 文件上传；
- WebSocket；
- 容器重启。
- LMS Adapter 的结构化输出契约；
- 旧教学制品仍可在 LMS 查看；
- 关闭 AI feature flag 后 LMS 基线仍可独立工作。

稳定后固定版本或 digest。

### 4.3 K12

更新代码前：

```bash
cd /srv/edu-stack/k12/repo
git status
git rev-parse HEAD
```

保存：

- 当前 commit；
- `books.yaml`；
- 自定义配置；
- 自定义脚本；
- 输出数据版本。

不要让 `git pull` 覆盖尚未备份的本地修改。

K12 数据升级不是普通代码拉取。升级前后必须分别记录：

- Git commit、Hugging Face revision/文件哈希和许可证；
- `datasetVersion`、卡片 manifest、内容哈希和课程 schema；
- 受影响的 LMS `CurriculumRef` 数量；
- 旧 evidence snapshot 的保留方式。

已存在的错题和教学制品继续引用旧版本快照；不得在后台静默把所有课程引用重映射到新数据。

## 5. 必须备份的内容

| 层次 | 必须备份 | 备份方法/说明 |
| --- | --- | --- |
| LMS MongoDB | Family、User、Task、Mistake、教学闭环、掌握事件、周报等 | `mongodump --oplog --archive`，不得复制运行中数据卷 |
| LMS 私有媒体 | `resource-data` 卷 | 停写/一致性窗口内归档，包含原题、手写订正、练习答案、打印素材 |
| LMS 部署 | `.env`、`docker-compose.ubuntu.yml`、Git commit、feature flags | 暂存后由 Restic 加密，密钥不写日志 |
| DeepTutor | `/srv/edu-stack/deeptutor/data` | 停止 DeepTutor 后备份完整 `/app/data` 映射 |
| 教育 AI 部署 | `compose.yaml`、`.env`、镜像 digest、Adapter 配置 | 加密；prompt/schema 版本必须可恢复 |
| K12 发布资产 | `data`、`cards`、`configs`、manifest、repo commit、`books.yaml` | 保存 `datasetVersion`、文件哈希和许可证 |
| 合法教材源 | `k12/input` 中无法重新取得的合法文件 | 单独加密并遵守教材版权，不因备份而公开 |

可选备份：

```text
/srv/edu-stack/k12/workspace
Docker 镜像归档
Python wheel 缓存
MinerU 模型缓存
```

`workspace` 很大且通常可重新生成，但需要断点续跑时应保留。

不需要备份 Docker 镜像层、`node_modules`、K12 Bench/Train 下载缓存或可由固定版本
重建的向量索引；但必须备份它们的版本清单和重建参数。

## 6. 一致性备份

每日自动备份沿用本地 Ubuntu 部署指南中的“MongoDB 逻辑归档 + 媒体卷 + 配置暂存 +
Restic 写 NAS”。AI 扩展启用后，在同一备份作业中增加以下步骤：

```bash
cd /srv/edu-stack
docker compose stop deeptutor
```

然后把 DeepTutor 数据、K12 发布资产、manifest 和无明文泄漏的配置加入当次 Restic
snapshot。LMS MongoDB 可以用 `mongodump --oplog` 获得一致逻辑备份；DeepTutor
当前没有与 LMS 共享事务，所以只需记录共同的 `backupId`、开始/结束时间和版本清单。

推荐清单：

```text
backupId
startedAt / completedAt
LMS Git commit
LMS feature flags
MongoDB dump filename and checksum
resource-data archive filename and checksum
DeepTutor image digest and /app/data checksum
K12 Git commit / datasetVersion / card manifest hash
promptVersion / artifactSchemaVersion / adapterVersion
```

启动：

```bash
docker compose start deeptutor
```

只在家长当日确实需要 AI 生成时重新启动；否则保持停止以节省内存。备份脚本不得使用
`docker compose down --volumes`，也不得在未验证路径时使用 `rsync --delete`。

## 7. 备份策略

推荐 3-2-1：

- 至少 3 份数据；
- 至少 2 种介质；
- 至少 1 份不在 ThinkPad 上。

建议：

- 每日：LMS MongoDB、私有媒体和部署清单；AI 启用后同时备份 DeepTutor 增量和教学版本清单；
- 每周：完整 LMS 配置、`/srv/edu-stack` 的必要资产和 K12 manifest；
- 每次升级前：版本快照；
- 每次新教材处理后：K12 输出快照；
- 每月：恢复测试。

API Key 和学生数据备份应加密。

NAS 只保存 Restic 加密仓库。Restic 密码必须另外保存在离线密码管理器；只存在服务器上的
密码文件不能算可恢复。至少每月在隔离临时目录执行一次实际 restore 和校验。

## 8. 迁移到新服务器

### 8.1 旧服务器

```bash
# 先按本地 Ubuntu 指南生成 LMS MongoDB + media 一致性备份
cd /srv/edu-stack
docker compose stop deeptutor
docker image inspect \
  "$(docker compose config --images | head -n 1)" \
  --format '{{index .RepoDigests 0}}'
```

记录：

- Ubuntu 版本；
- Docker 版本；
- Compose 版本；
- DeepTutor image digest；
- DeepTutor 设置；
- embedding provider/model/dimension；
- K12 Git commit；
- K12 数据版本；
- LMS Git commit、MongoDB dump 和媒体归档校验和；
- prompt/schema/adapter 版本；
- feature flag 状态。

优先从同一个 Restic snapshot 恢复，而不是跨服务器直接同步运行目录。确需 `rsync`
迁移 `/srv/edu-stack` 时，DeepTutor 必须保持停止，目标路径要先 dry-run 并确认；LMS
MongoDB 仍从逻辑 dump 恢复，不能复制运行中的 `mongo-data`。

### 8.2 新服务器

1. 安装与验证 Ubuntu、Docker 和 NAS/Restic；
2. 恢复 LMS 代码、Compose、Secret 和固定版本；
3. 恢复 MongoDB 逻辑 dump，校验家庭/孩子/任务/错题数量；
4. 恢复 `resource-data`，抽查原题和手写订正的授权读取；
5. 保持 AI feature flag 关闭，先验收 LMS 基线；
6. 恢复 DeepTutor `/app/data`、相同镜像 digest 和 Adapter 配置；
7. 恢复 K12 卡片、manifest 和准确的 `datasetVersion`；
8. 启用家长侧 AI 测试，验证旧教学制品和一次新生成；
9. 最后按需启用孩子学习包、周报和提醒。

```bash
cd /srv/edu-stack
docker compose config
docker compose pull
docker compose up -d
docker compose ps
docker compose logs --tail=200
```

### 8.3 向量索引

可以直接迁移的条件：

- DeepTutor 版本一致；
- embedding provider 一致；
- embedding model 一致；
- dimension 一致；
- 文档分块方式一致；
- 知识卡片一致。

任一条件改变时，建议重新索引。

因此必须保留原始 Markdown 知识卡片。

## 9. 回滚

升级失败时：

1. 立即关闭 AI feature flag，保持 LMS 基础任务、错题和附件可用；
2. 停止新 DeepTutor/Adapter 容器；
3. 恢复旧 Compose、镜像 digest、prompt/schema 和 K12 manifest；
4. 只有 DeepTutor 数据发生不兼容写入时才恢复升级前 `/app/data`；
5. 若 LMS schema/数据也发生变化，按单独迁移回滚方案从一致性备份恢复，不能即兴修改真实数据；
6. 验证家长登录、孩子 PIN、错题、私有媒体、旧教学制品和一次受控生成；
7. 保留脱敏失败日志和新版本数据副本用于诊断。

不要在恢复完成前删除旧备份。

## 10. 网络安全

默认 Compose 使用：

```yaml
ports:
  - "127.0.0.1:3782:3782"
```

这意味着只有主机本地可访问。

推荐远程方式：

1. SSH Tunnel；
2. Tailscale；
3. Caddy + HTTPS + 身份验证。

不建议：

- 公网直接开放 `3782`；
- 公网开放 `8001`；
- 关闭身份验证后对外服务；
- 通过不可信 Wi-Fi 明文访问；
- 使用默认弱密码。

完成 LMS 集成后，家庭客户端只访问 LMS Gateway/Web。DeepTutor `3782` 只为管理员排错
临时保留回环绑定，`8001` 和 Graph API 只在内部 Docker 网络可达。

Docker 官方提醒：Docker 发布端口可能绕过部分 UFW 规则。绑定 `127.0.0.1` 可以显著降低风险，但公开部署仍应使用 `DOCKER-USER` 链、反向代理和精确访问控制。

## 11. SSH 安全

建议：

- 使用 SSH Key；
- 禁止 root 远程登录；
- 关闭密码登录前确认 Key 可用；
- 修改配置前保留一个已登录会话；
- 定期检查登录日志。

检查：

```bash
sudo journalctl -u ssh --since "24 hours ago"
last
```

## 12. API Key 安全

- Key 不写入 Git；
- Key 不写入公开 Markdown；
- Key 不发到聊天截图；
- DeepTutor 数据目录权限应受限；
- 备份应加密；
- Key 泄漏后立即轮换；
- 不同服务使用不同 Key；
- 尽可能设置余额和用量告警。

检查权限：

```bash
find /srv/edu-stack/deeptutor/data -maxdepth 3 -type f -ls | head
```

## 13. 学生隐私

使用云端 DeepSeek 和 embedding 时，问题和部分资料可能被发送到云端。

不要上传：

- 真实姓名和联系方式；
- 学校、班级、学号组合；
- 身份证件；
- 账号密码；
- 未脱敏的成绩表；
- 受限制的内部资料。

建议用本地随机学生 ID：

```text
student_001
```

而不是直接使用真实姓名。

第一阶段还禁止把原始手写图片、媒体签名 URL、完整错题档案或完整周报发送到 LLM
或 embedding。家长在 LMS 中确认后的标准错因、课程节点和脱敏聚合才可以进入
最小上下文；调用日志仅记录 `operationId`、模型、token、延迟和结果哈希。

## 14. K12-KGraph 许可证

### 14.1 数据

知识图谱、K12-Bench、K12-Train：

```text
CC BY-NC-SA 4.0
```

含义：

- BY：署名；
- NC：不得用于商业目的；
- SA：公开改编版本时使用相同许可证；
- 修改时标明修改；
- 不得增加阻止许可证权利的限制。

家庭学习和非商业研究通常适合。收费教学产品、商业 SaaS、商业数据服务不能直接使用这些数据，除非取得单独许可。

### 14.2 代码

K12 仓库代码：

```text
MIT License
```

可以修改、部署和分发，但需保留版权和许可声明。

### 14.3 DeepTutor

DeepTutor：

```text
Apache License 2.0
```

分发修改版时需遵守许可证、版权和 NOTICE 要求。

## 15. 教材版权

开源代码和 K12 数据许可证不会自动提供教材 PDF 的版权授权。

即使技术上可以转换其他教材，也不代表可以：

- 公开教材全文；
- 分发 PDF；
- 商业销售衍生知识库；
- 把大量受保护内容加入公开服务；
- 删除出版社署名。

公开发布或商业使用前应单独进行版权评估。

## 16. 故障排查顺序

### 16.1 页面打不开

```bash
cd /srv/edu-stack
docker compose ps
docker compose logs --tail=200 deeptutor
curl -I http://127.0.0.1:3782
```

### 16.2 SSH Tunnel 不通

检查：

- SSH 会话是否仍在；
- 本地 `3782` 是否被占用；
- 服务器 curl 是否成功；
- SSH 命令中的服务器地址是否正确。

### 16.3 LLM 不工作

检查：

- DeepSeek Key；
- Base URL；
- 模型名；
- 余额；
- DNS；
- HTTPS；
- DeepTutor 日志。

### 16.4 知识库索引失败

检查：

- embedding endpoint；
- 模型；
- dimension；
- 文档格式；
- 内存；
- 旧索引；
- API 限速。

### 16.5 K12 运行失败

按层排查：

1. Python 虚拟环境；
2. 包依赖；
3. demo；
4. 发布文件；
5. LLM API；
6. MinerU；
7. 单章节；
8. 单本教材；
9. 全量。

不要一开始就在完整流水线上排错。
