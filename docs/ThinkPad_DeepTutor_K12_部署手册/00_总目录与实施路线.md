## 1. 架构结论

这不是“DeepTutor 加一个图谱”的独立网站，而是三个边界清晰的组件：

- **LMS 是唯一业务与学习档案中心**：保存家庭、孩子、任务、错题、手写附件、家长审核、掌握证据、周报和提醒。
- **DeepTutor 是受控教学内容生成器**：生成讲解、提示、例题和变式题，不直接修改 LMS 业务数据。
- **K12-KGraph 是只读课程结构库**：提供课程节点、教材位置、先修关系和证据，不保存孩子状态。

孩子通过 iPad 只访问 LMS。DeepTutor Web 仅供家长或管理员在独立验证阶段使用；完成
LMS 适配后，孩子端不应跳转到 DeepTutor 管理界面。

## 3. 当前环境状态

下列版本是既有机器曾完成的验证记录，不是安装本文的硬性版本要求：

- Ubuntu 26.04 LTS 已安装；
- Docker Engine 29.1.3 已安装；
- Docker Compose v2.27.0 已安装；
- Docker daemon 已设置为开机启动；
- amd64 测试容器已经成功拉取并运行；
- 当前用户可以使用 `docker compose`。

正式重装时优先选择仍在标准支持期内的 Ubuntu Server LTS，并按官方 Docker 文档安装
当前受支持版本。`docker` 用户组具有接近 root 的主机权限，只能加入可信账户。

## 4. 推荐实施路线

### 阶段 0：冻结并验收 LMS 基线

- [ ] 按 [本地 Ubuntu 部署指南](../deployment/local-ubuntu-deployment.md)运行家庭 LMS；
- [ ] 完成家长登录、孩子 PIN、错题和私有附件的真实验收；
- [ ] 完成 MongoDB 逻辑备份、媒体备份和一次 NAS 恢复演练；
- [ ] 记录 LMS Git commit、Compose 配置和 feature flag；
- [ ] 确认仅通过局域网或 VPN 访问，不直接暴露公网。

在这一阶段没有完成前，不把 AI 扩展接入孩子的正式学习流程。

### 阶段 1：管理员独立验证 DeepTutor

- [ ] 检查 swap/zram 和磁盘余量；
- [ ] 创建 `/srv/edu-stack/deeptutor/data`；
- [ ] 使用回环地址启动固定版本的 DeepTutor；
- [ ] 通过 SSH Tunnel 由家长访问；
- [ ] 配置云端 LLM 和 embedding；
- [ ] 用虚构样例验证讲解、结构化输出和重启持久化。

此时 DeepTutor 不读取真实孩子档案，也不保存权威掌握度。

### 阶段 2：最小 K12 课程试点

- [ ] 固定 K12 仓库 commit 和数据版本；
- [ ] 只选一个学科、一个年级、一个章节；
- [ ] 生成少量带稳定 ID 的课程知识卡片；
- [ ] 人工核对教材位置、先修关系、许可证和证据；
- [ ] 将 `nodeId + datasetVersion` 作为 LMS `CurriculumRef` 的候选来源；
- [ ] 不在 X230i 常驻运行 Bench、Train、MinerU 或全量抽取流水线。

### 阶段 3：LMS 家长侧教学闭环

- [ ] 先实现课程映射和错因人工确认；
- [ ] LMS 通过内部适配器向 DeepTutor 发送最小化、去身份化上下文；
- [ ] DeepTutor 返回结构化候选讲解，LMS 校验后保存为教学制品；
- [ ] 家长审核并点击“发布给孩子”；
- [ ] 孩子只在 LMS iPad 页面查看讲解、上传 Apple Pencil 手写订正；
- [ ] 家长审核通过后，LMS 再请求生成变式练习；
- [ ] 最终掌握度只依据家长确认的证据更新。

### 阶段 4：LMS 周报与提醒

- [ ] 先在 LMS 内增加“待家长审核、生成完成、复习到期”提醒来源；
- [ ] 将家长确认的错因、教学闭环和复习状态纳入 LMS 周报；
- [ ] 周报和提醒只从 LMS 权威状态确定性派生；
- [ ] 任何外部通知渠道都需要家长明确授权和可撤销配置。

### 阶段 5：按价值决定是否启用 Graph API

知识卡片试点证明多跳先修查询确实有价值后，再启用轻量只读 Graph API。当前规模优先
JSON/SQLite/NetworkX，不在 X230i 引入 Neo4j、Elasticsearch 或独立向量数据库。

## 5. 8 GB 主机的运行原则

1. LMS 基线常驻；DeepTutor 采用按需或限定时段运行。
2. K12 数据转换、MinerU 和索引重建不与正式 LMS 高峰同时执行。
3. 云端承担 LLM 和 embedding；不在本机运行 7B/14B 模型、vLLM 或重型 OCR。
4. DeepTutor 独立验证时只发布 `127.0.0.1:3782`；`8001` 默认只在容器/内部网络使用。
5. 完成 LMS 集成后，DeepTutor 和 Graph API 不对孩子、局域网或公网直接开放。
6. 先小数据、单章节、单并发；确认内存、成本和教学价值后再扩大。
7. 原始课程卡片、数据版本和 LMS 权威记录优先于可重建的向量索引。
8. 所有镜像、prompt、schema、embedding 模型和 K12 数据都记录版本。
9. 所有升级先备份、再验证、可回滚；不使用浮动 `latest` 作为长期运行版本。

## 6. 资源与目录默认值

| 项目 | 建议值 |
| --- | --- |
| LMS | 按仓库 `docker-compose.ubuntu.yml` 与本地部署指南运行 |
| DeepTutor 管理验证入口 | `127.0.0.1:3782`，SSH Tunnel 或 VPN |
| DeepTutor FastAPI | 容器内部 `8001`；仅适配器调试时回环发布 |
| DeepTutor 持久化 | `/srv/edu-stack/deeptutor/data` → `/app/data` |
| DeepTutor 资源上限 | 首测 2.5～3 GB、约 1～1.5 CPU，按实测调整 |
| K12 运行范围 | 一个学科、年级和章节的版本化发布数据 |
| K12 抽取并发 | 1；尽量在其他机器或离线维护窗口运行 |
| 模型推理 | 云端 API；模型名从服务商当前 `/models` 或官方文档确认 |
| 默认远程访问 | Tailscale/其他 VPN；初装排错用 SSH Tunnel |
| 备份位置 | 家庭 NAS 上的 Restic 加密仓库，另保留离线恢复密码 |
