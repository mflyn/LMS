ENTRY-05 设计 P2 的永久反例与正例要求（保留原预期，执行结果另列）：

1. 保持同一登录页挂载，输入 A 的合成 PIN 但不提交，先验证输入确实存在、登录调用为 0。参数化切换 A -> B（分别只换 childId、只换 familyId）、A -> 无效/无入口 -> B、A -> B -> A、A -> 无效/无入口 -> A、专属 -> 手工 -> 专属，以及手工模式编辑任一目标字段。通过路由/fragment 变化模拟前进返回，不能靠卸载重建表单掩盖清理缺失；两孩子可使用相同合成 PIN，避免错误凭据拒绝偶然掩盖旧输入复用。
2. 每个变化点断言旧 PIN 已清空，未重新输入前触发表单提交也零 POST；最终回到原目标仍为空。除即时清空外，单独制造入口已变化而旧输入/提交闭包尚在的时序，断言提交前意图校验拒绝旧 PIN，不能只靠按钮 disabled。每次对比变更前后的孩子/家长会话、退出标记、原 UUID/正文命令及未知写入锁不变；使用另一孩子标签页保留会话和预置合成命令，断言没有 logout、退出广播、命令删除或业务写调用，避免仅比较空存储的空洞通过。
3. 合法正例：不改模式/目标的普通重渲染、清错误，以及同一专属目标的参数顺序/大小写规范化变化均保留已输入 PIN，显式提交恰好一次原三字段请求；入口变为 B 后必须重新输入 B 的 PIN，才允许恰好一次 B 请求并接受匹配的响应。另验证完成手工目标编辑、重新输入 PIN 后仍能正常登录。ENTRY-08 则在 B 已重新输入或已发送新请求后释放 A 的旧成功/失败，等待旧 finally 结束再检查新输入/会话不受影响。

ENTRY-08/09 的屏障必须等到响应处理结束后核对会话、URL、页面和命令状态，不能只断言旧按钮消失。测试 finally 释放阻塞并等待路由/请求收尾，传播清理异常，保证失败也能退出；只清理本次已创建合成资源。

1. 先在原实现上建立“有效专属入口只输 PIN”“不同目标不误继续”“入口变化后未提交 PIN 不得复用”和“入口变化/卸载后旧 PIN 不得保存”的红灯；按原层次实现。手工表单兼容测试保留。
2. 定向运行入口工具、家长孩子页、孩子登录/切换、`ChildAuthContext` 和 `familySession` 测试；永久反例与合法正例均执行。对保存前意图检查、不同目标分支至少各做一次临时删除保护的变异；本次 P2 另分别移除未提交 PIN 清理、提交前输入归属检查，必须分别在输入清空、零 POST 断言处失败，不能仅依赖旧响应用例失败。验证后还原，不扩建变异框架。
3. 运行前端完整默认回归、构建和现有 lint；后端只需原孩子登录/权限相关套件，无后端代码变化不机械重跑全仓历史。若共享层实际改动扩大，扩大受影响调用方回归并说明依据。

独立复评首轮发现两项 P2 测试保护缺口，保留首轮结论，未判定为新增产品逻辑漏洞：

1. 原卸载变体先触发 ABA，无法独立证明卸载保护。现单独保持 Provider、目标与 fragment 不变，不发新请求，仅卸载登录页后释放旧 200/401；检查存储、命令、退出标记、导航与持久 Context 错误。另保留 ABA 与较新 attempt 用例。
