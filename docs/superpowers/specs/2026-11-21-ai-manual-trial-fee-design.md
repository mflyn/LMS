## 2. 不变的输入、权限与发送边界

- 仅现有两条 system/user 纯文本、固定模板及允许字段；无隐式历史、图片、工具、附加角色或模型自行重试。
  外发前仍须家长确认脱敏；不自动加入孩子姓名、ID、私有图片、作答或未批准来源。
- 保留解压后原始JSON和完整内部operation正文的32 KiB限制；新增版本也核对最终SDK出站正文的UTF-8字节不超过32768。
  LMS在新预留前拒绝，远端在持久claim及SDK前核对，最终transport必须等于冻结wire；不截断文本。
  32 KiB不是8192 tokens，不是供应商上下文或计费上界证明；供应商超上下文拒绝也不能自动再试。
- 输出参数仍最多4096 tokens，thinking=disabled、tools=[]、stream=false，底层 attemptLimit=1；

## 3. 估算与共享占位

新费用模式为 `estimate_only`，估算方法固定为 `reference-8192-4096-v1`：
`ceil(8192 * inputPriceMicrosPerMillion / 1000000) + ceil(4096 * outputPriceMicrosPerMillion / 1000000)`。
8192是参考规划输入量，不是实际计数或强制输入token上限；4096是输出额度，不是预计必定生成的数量。
不实现新的tokenizer或字符估算器。价格用已核对profile，整数CNY微元，BigInt精确计算并验证持久字段安全整数。
币种换算或计价组成无法核对时不得填零或套旧价格；配置须记录可审查来源/核对时间/有效期，页面可见。

`estimatedReservationMicros` 替代新契约中的 `reservedCeilingMicros`，是准入占位而不是扣款、最高账单或最高授权。
家长确认 `estimateAcknowledged=true`，表示理解实际可能超估算；不允许把旧 `maxAuthorizedCostMicros` 自动转换为此确认。
模型/价格/估算方法/费用模式/金额/期限/完整消息都绑定预览摘要和持久命令，任何一项改变须重新预览与确认。
预留事务、共享槽后的最终claim及transport仍检查profile和不可延长的sendNotAfter；过期不静默续期或重报价。

复用家庭单次/日/月和experiment账户、跨AI-1/AI-3全局发送槽，不开第二资金池。
预算准入仍比较已记账金额 + 全部未决占位 + 本次估算，占位跨日/月延续；改变时区/配置/重启不重置。
这些只是后续请求准入阈值，单次和整轮均不承诺费用硬上限，也不控制同一供应商账号其他工具的消费。

首轮建议最多3个授权提交名额，具体数字在另行真实试用授权时确认；缺少批准名额/预算则零发送。
复用experiment账户保存本轮批准名额及已用数，在生成预留同一事务内消费一个、绑定唯一原命令；
同命令重放不重复消费，事务回滚不消费。已提交名额即使后来证明未发送也不自动补回，保守保证本轮尝试不超名额。
不新增试用批次管理页面；名额不得因切profile、换家庭、进程重建、跨日或重新命名配置自动重置。
历史发送不倒扣新名额，但所有旧未决费用/共享槽必须先按旧契约处理，不能以新模式绕过。
容量只在新预留事务检查；claim/原reserved接续只校验本命令已持久占用同一本轮名额的证明，不重复消费，
不因总剩余为零拒绝第三个已占名额的命令。证明绑定experiment授权版本、ownerProfile和原Job/Command，缺失或错配拒绝。
人工试用配置下，历史v1 reserved没有该证明，保持原记录且禁止恢复出站；不自动绑定/转换，不能用新UUID丢掉原占位。
旧v1已发命令仍可按旧规则查询收敛；旧未发命令只在可证明未发送时按原CAS终结，其他情况继续阻断。

## 4. 结果记账、停发与恢复

| 可信证据 | 记账与候选 | 后续付费发送 |
| --- | --- | --- |
| succeeded且内容/usage有效，按冻结报价计算金额不超过估算 | 原子保存待审核候选、按usage计价记账并释放估算差额；并非供应商账单已对账 | 仍须新的人工确认、名额及共享预算准入 |
| succeeded且内容/usage有效，金额超过估算 | 不截断金额、不丢有效候选；原子记全额、消除该笔占位并锁存停发原因 | 家庭及experiment停发，覆盖AI-1/AI-3及其他家庭的新付费发送 |
| succeeded且内容有效但usage缺失 | 候选可保留；reserved_unknown，金额不填零、不释放占位 | 同上，费用未知停发 |
| failed_sent且usage有效 | 按usage计价记账，不生成候选；超过估算同样停发 | 非超估算且费用完整时仍遵守后续人工准入，绝不自动再试 |
| unknown、用量/响应不可信、矛盾终态或发送后未落盘结果 | 不返回假成功，保留原映射/占位/必要共享槽及失败证据 | 停发；404、超时、过期、租约失效不构成退款证据 |
| 连续存储下可靠failed_not_sent | 原命令按原owner/阶段CAS终结并释放费用占位，不回补本轮提交名额 | 不自动生成；下一命令仍须新确认且不能越过其他停发原因 |

新版本usage.inputTokens允许非负安全整数超过参考8192；outputTokens仍不得超过4096，类型/合计一致性/实际模型身份仍核对。
仅参考输入超8192而金额未超估算不误拒绝；按usage和冻结单价得到的是“用量计价金额”，不冒充精确供应商扣款。
算术溢出、价格快照不可信或不完整计费项目按费用未知处理，不通过截断、负数或忽略字段使结算成功。

停发复用持久账户halted及有界原因（超估算/费用未知），先于释放全局槽生效并与结算/候选写入同事务。
最终claim必须条件写同一共享预算修订号，不能只读布尔值后再发，防结算停发与另一个请求抢槽竞争。
该检查包含已消费名额的精确原命令归属，不重新申请名额；对新请求的“名额耗尽”提示不替代原命令canRecover判定。
有效结果和停发事务提交未知时保留锁，查询原持久结果，不能新建命令。别的家庭只收到通用停发提示，不泄漏原因所属人/内容。
服务恢复后在允许新发送前核验旧reserved_unknown、UNKNOWN、超估算及停发状态；无从证明完整性则隔离，不能启动时清锁。
停发禁止新generate、reserved恢复出站及任何新claim；仍允许有权限的原operation只读查询和可靠终态幂等记账，
不能因当前预算不足或halted阻止已有账务收敛。后续证据补齐不自动解除锁存停发，另行人工决定；本批不建解除/退款API。

原actor重登先发现并显式恢复原命令。已到dispatching/UNKNOWN仅查询原operation；旧accepted不由重启或重复PUT再次派发。
只有连续存储且持久证据明确尚未越过本地dispatching的reserved可显式接续，须通过全部实时准入且使用原UUID/hash/期限。
即使模型“可能未收到”，claim后也不自动补发。预算变化、退出、关页面、切孩子均不能丢弃未知保护。

## 5. 版本兼容、启停与回退

公开新生成相关schema为ai1-min-v2 / ai3-min-v2；内部为ai1-provider-operation-v2 / ai3-provider-operation-v2。
不是全部教学接口升级。路径不变，具体允许的动作及闭合字段见API增补。旧v1缺feeMode仍严格按旧契约解释，
不能默认为估算，也不能用同一operationId改schema重发；同键异正文继续409。
新预览/原命令保存费用模式和版本，旧记录只读投影可明确标注strict，不修改旧存储/hash。
旧预览不能按新费用确认提交，旧未决命令不能重新封装；对端不识别v2即拒绝，不降级v1或直连模型。
真实启用前两端必须已支持新版本、查询恢复可用、报价核对与试用批准完整；配置开关本身不是证据。
旧 `AI1_PROVIDER_PROFILE_CONFIRMED` 的严格计数含义不改写：实现需为v2显式区分“人工估算试用配置已核对”，
两种互斥配置不能混用，现有只有严格确认的配置不得自动升级；当前默认off不变。

回退优先关闭新发送、保留识别v1/v2的query-only程序来收敛已发命令。已有v2持久记录后，不可直接回退到不识别v2的二进制；
不删记录/恢复旧库/重建账本来消除停发。无v2记录时才可按受控验证回退；服务器变更必须另行授权。
