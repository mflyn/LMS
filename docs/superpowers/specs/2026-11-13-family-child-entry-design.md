## 1. 目标与取舍

家长在已有孩子档案中打开或复制专属入口，孩子将其保存为自己的书签；日常打开入口后只输入 4 至 6 位 PIN，不记忆或复制家庭 ID、孩子 ID。两个 ID 仍由原服务端验证，不因前端隐藏而省略。

| 方案 | 取舍 |
| --- | --- |
| A：每个孩子一个入口 + PIN | 本轮已选。复用现有接口、档案、页面和标签页会话，不新增账户或设备数据。 |
| B：家庭设备内选孩子 + PIN | 后置；需要额外定义设备首次设置、名单保存/清除和换家庭规则，不纳入本轮。 |
| 只输入 PIN、由服务端查找孩子 | 不采用；PIN 不是全局唯一身份，不新增匿名家庭/孩子发现。 |

本轮不做二维码、短链服务、设备配对、免密登录、PIN 找回新流程、全局用户名、后台换号或新恢复框架；不修改后端认证、限流、模型、数据库、部署配置。入口不保证帮助不同孩子记住相同 PIN 的区别，登录成功后仍须核对实际返回的姓名。

## 3. 入口格式与隐私边界

客户端链接格式如下；尖括号为占位符，不是可直接发送的数据：

```text
<当前站点 origin>/child/login#familyId=<24位十六进制ID>&childId=<24位十六进制ID>
```

- 用现有 `URL` / `URLSearchParams` 生成与解析。路径固定 `/child/login`，origin 取当前站点；不接受外部 origin、任意路径或 `next`/`redirect`。本轮不改变部署的根路径假设。
- 仅 fragment 携带这两个定位字段；不在 query、路由路径、日志或遥测中增加 ID。fragment 不随普通 HTTP 请求/Referer 发送，但仍可被同源脚本、浏览器历史、书签、剪贴板及其同步读取，不能宣称加密或保密。
- 两个参数都必须恰好出现一次，值必须完整匹配 24 位十六进制，规范化为小写；参数顺序可交换。fragment 含 `#` 的原始长度上限 256 个字符；空值、缺项、重复项、未知参数及解析后不合法的值一律拒绝。不将非法输入截断、部分采用或与旧目标拼接。
- 不含姓名、头像、PIN、Token、家长会话、任务号或业务命令。身份名称只能来自已认证会话，不信任 URL 的展示身份。
- 此链接只是定位信息，不是访问凭证，也没有新增吊销机制。链接被复制后仍需有效 PIN；PIN 重置继续撤销旧孩子 Token，但不改变这两个 ID，所以旧书签可使用新 PIN。
- 不提供匿名孩子名单、头像或家庭查询。仅打开链接不自动发 PIN 登录、业务写入或恢复请求，不读取目标孩子的私有资料。
- 不新增“记住此家庭/孩子”的 localStorage/sessionStorage 数据。刷新登录页依靠原 fragment；进入业务页后依靠现有已认证会话，不从片段构造会话。

## 4. 家长与孩子交互

### 4.1 家长准备入口

在 `/app/children` 的每个现有孩子行增加“打开孩子入口”和“复制孩子入口”，沿用现有图标库、按钮样式和可访问名称。前者新开标签页，采用 `noopener` / `noreferrer`；不把父页已有孩子凭据复制给目标页。

动作仅在当前家长会话有效、`familyStatus=ready` 且行属于当前 `FamilyContext.children` 时可用；点击时再核对会话快照、家庭和行，旧家长/旧家庭的陈旧闭包不得生成或打开入口。不为生成链接新增网络查询，也不能将此检查当作替代后端权限。

复制失败、剪贴板不可用时，在当前仍有效的家长视图显示只读链接供手工选择；不得虚报“已复制”，不得请求长期剪贴板权限。异步复制返回前切换账号/家庭时，不显示旧成功消息或旧回退链接。已经交给系统剪贴板的内容无法保证撤销，因此动作前校验，不把事后清理 UI 宣称为撤回剪贴板。

家长仍使用现有方式设置/重置 PIN；不根据是否生成了链接推断 PIN 已配置。准备入口不会自动退出家长或孩子；共享设备交给孩子前，家长仍应退出家长账号，标签页隔离不等于浏览器配置文件级权限隔离。

### 4.2 登录页状态

| 当前状态 | 展示与允许动作 | 不允许的副作用 |
| --- | --- | --- |
| 匿名 + 有效专属入口 | “孩子登录”、PIN、提交按钮；默认不显示两个 ID 输入框。PIN 校验/错误规则保持原样。 | 不自动提交、不猜测姓名、不加载兄弟姐妹资料。 |
| 匿名 + 无 fragment | 提示使用家长准备的入口；提供显式“手工填写标识”，展开原三字段表单。 | 不自动恢复上一个孩子或家长选中的孩子。 |
| 匿名 + 无效 fragment | 明确提示入口无效，禁止该入口提交；可重新打开正确书签，或显式清除入口后进入手工表单。 | 不静默退回旧 ID、不边报错边自动登录。 |
| 已登录 + 入口目标与现有 familyId/childId 均相同 | 显示真实会话姓名，明确选择“继续使用”或原切换动作。 | 不自动跳转；不重新发 PIN 请求。 |
| 已登录 A + 有效入口 B 不同 | 提示当前实际登录 A、该入口指向另一身份；提供“切换到此入口”和“保留当前孩子”。 | 不以 B 的入口直接进入 A，不免 PIN 切为 B，不将 B 的 ID 写入 A 会话。 |
| 已登录 + 无入口/无效入口 | 无入口沿用原显式继续/切换；无效入口另提示无效，只能显式继续原身份或换正确入口。 | 不用原会话掩盖无效入口，也不因坏链接自动退出。 |

选择“切换到此入口”必须先使用现有未提交内容/未知结果提示。取消时不主动退出、不清草稿/命令、不写退出标记，保留当前身份且不自动进入任务页；确认后才对原孩子调用既有退出流程，再保留已校验 B 的 fragment 展示空 PIN 表单。必须由 B 重新输入 PIN。

确认动作绑定弹出提示时的会话快照和入口意图，确认返回后再次核对；期间原身份退出、出现较新会话或目标改变，丢弃旧确认并重新呈现当前状态，不用旧确认清除新身份。取消的零副作用以提示出现前为比较基准，不承诺恢复用户此前离开业务页时已丢失的未保存内存草稿；各模块的原草稿/未知命令规则仍保留。

“保留当前孩子”是明确选择 A，替换路由到原 `/child/today` 并去除 B 的 fragment，不请求 B 的资料。用户之后仍可重新打开 B 的书签。

PIN 从输入时起绑定当前登录页的入口意图代次，不等到发送请求才绑定。匿名状态下目标 A 变 B、入口移除或变非法、专属/手工模式互换，以及手工目标字段编辑时，立即清除上一意图的 PIN，即使尚未发送任何请求；A -> B -> A、A -> 无效/无入口 -> A 也不恢复旧值。新意图必须重新输入 PIN。普通重渲染、错误提示变化、submitting 更新，以及同一合法专属目标仅参数顺序或十六进制大小写变化，不新建意图、不清除当前输入。

上述输入清理只作用于登录表单和归属该意图的请求资格，不调用退出、不写退出标记、不改变已有会话或业务命令；已有认证身份仍按上表和显式切换确认处理。提交前再次核对 PIN 所属意图与当前模式、目标一致；不匹配或新意图尚未输入合法 PIN 时零 POST，不仅依赖异步副作用稍后清空字段或按钮禁用。不得将旧 PIN 重新绑定给新意图。

提交时固定本次意图代次、规范化目标和 PIN，成功后只接受身份与目标一致且意图仍有效的服务端响应，复用现有保存逻辑并 replace 到 `/child/today`，不带 fragment。所有结束路径清除本次 PIN；失效请求的 finally 不得清掉较新输入或改动较新页面的提交状态。

### 4.3 刷新、退出与重新登录

- 登录页刷新：有效 fragment 可重新解析，但 PIN 不保留，也不自动重发。
- 已登录页刷新：继续现有本标签页会话检查；不以书签替代有效会话。
- 显式退出、普通“切换孩子”、过期跳转仍可回到原通用 `/child/login`；本轮不增加退出后的定位缓存或改造全局过期跳转。孩子重新打开自己的书签即可只输入 PIN，手工表单仍作兼容入口。
- 多个书签由家长命名并保存，不承诺网页能自动创建书签。复制标签页/浏览器恢复仍可能带来原身份，必须执行第 4.2 节已有身份判断，不能把新链接当成已登录新孩子。
- 认证失败统一显示原错误，保留已校验目标并清 PIN；限流按原规则等待；网络失败只允许用户重新输入并显式登录，不自动重试。登录不是新的业务幂等命令，不为登录创建业务 UUID。

## 5. 在途响应、切换清理和原命令恢复

入口变化新增了一个现有 Context 不直接感知的失效原因：旧 PIN 请求在目标已经变化或登录页卸载后返回。仅在页面 `await login()` 后决定不导航不足以防止旧会话已被保存。

因此，实施时在现有 `ChildAuthContext` 内复用 attempt 代次，增加窄的、按本次请求归属取消/检查机制：入口从 A 变 B、移除或变非法、登录模式切换、登录页离开/卸载，都使旧请求失效；手工模式的目标字段变化也不能保留旧请求资格。相同目标 A -> B -> A 仍是新代次，不能只比较最终两个 ID。第 4.2 节的未提交 PIN 清理与这里的在途请求失效使用一致的意图变化规则；未发请求也必须清理旧输入，不能用请求 attempt 的存在与否决定是否清理。普通渲染、更新 submitting 或清除旧错误不构成新意图，不得因此取消正常登录。

- 在 `saveChildSession` 前以及写入错误状态/返回成功前确认页面意图仍有效；原 attempt、原会话快照、`captureChildLogin`/`assertChildLoginCurrent` 和退出标记检查缺一不可。
- 取消只作用调用方拥有的在途 attempt；旧页面收尾不得取消较新的 attempt。成功完成后页面卸载也不得撤销刚成功的会话。
- 只使旧请求失效，不用 `logout()`、广播退出或删除命令模拟取消。不能因改变/取消入口而影响另一个孩子或家长，也不能靠清理当前新身份来处理旧 200/401。
- 请求已发送无法保证服务端不签发 Token；客户端必须拒绝使用迟到响应，不能把 AbortController 或按钮禁用当作完整保护。
- 新入口不改变现有显式退出清理、自然过期和反思/错题未知写入的差异化政策；不得将全部存储一键清空或为方便切换解除未知写入保护。
- 未知完成提交在当前会话内仍重试原 UUID/正文；退出重登后仍由原 actor 发现并显式恢复服务端持久命令。只打开链接不恢复；换成 B 不能看到/恢复 A 的命令，也不能为 A 生成新 UUID。已知成功/历史终态不能重复发布或发星。
- 会话存储失败仍拒绝登录，不退回共享孩子 Token；同孩子跨标签显式退出、另一孩子不受影响、家长独立会话及私有媒体迟到响应保护均保留。

## 6. API 兼容、范围和回滚

网络请求保持 `POST /api/auth/child-pin-login`，请求体仅为 `familyId`、`childId`、`pin`。成功仍读取 `{ success: true, data: { token, child } }`；统一 `401 INVALID_CHILD_CREDENTIALS`、`429 PIN_LOGIN_RATE_LIMITED` 和既有网络/本地存储错误处理不变。不改变家长/孩子权限或放宽任何服务端 ID 校验。

主要实施影响面限于家长孩子页、孩子登录页、小型入口工具、ChildAuthContext 的请求归属失效及必要的切换目标接线。现有 `familySession.js` 若确需改动，必须先证明当前接口不足，扩大对应调用方回归，不能顺带重构。用户指南应待实现验收后再更新，不把本设计写成已上线。

前端变更可整体撤回到本基线，不迁移数据、不修改后端；撤回后专属链接可能不能自动填 ID，使用原手工登录即可。回滚不撤销 PR #44 的标签页/在途 PIN 安全修订，不清理业务记录或未知命令。

## 8. 限定本地实现与交付边界

本批新增 `childEntry` 定位工具和家长 `ChildEntryActions`，调整孩子登录页与 `ChildAuthContext.login` 的可选 `isCurrent` 请求归属检查；复用原 PIN API、会话存储、退出标记和业务命令恢复，不修改后端、`familySession` 或任何原命令模型。

页面实现把未提交 PIN 和在途请求绑定同一意图对象。目标/模式变化创建新对象；提交闭包、保存响应和 finally 均核对原对象及当前 fragment，卸载使对象失效；普通重渲染与等价定位保留输入。StrictMode 的模拟卸载后重建合法意图并刷新提交闭包，保留首次输入的永久正例。

本地独立复评提出的卸载用例与浏览器处理屏障两项测试保护缺口，按[测试方案第 5 节](../../development/family-child-entry-test-plan.md#5-本地实现映射与评审修订)补强。开发实跑、独立复验及原失败分别绑定到工程证据，不覆盖第 7 节历史候选，也不将设计问题关闭等同工程验收。

仍不增加账号体系、匿名孩子名单、二维码、设备信任或 PIN 缓存；正式真人入口不自动升级。验收后是否交付 Git、如何让测试/评审线程切换实例，需后续授权；当前回滚仍只涉及前端增量，不动原标签页隔离与业务记录。
