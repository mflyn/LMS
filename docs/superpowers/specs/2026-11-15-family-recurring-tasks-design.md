## 1. 产品范围与待批准取舍

目标：家长设置“每周一至周五跳绳”，孩子每日完成、提交作品，家长按所见版本确认，孩子回看；不再每天手工创建。
一份计划对应多个 GrowthTask，每条仍只代表一次发生。既有任务、求助、作品、审核、错题、周报及星星规则不重做。

以下取舍已获用户本轮设计批准，不代表已实现：

| 决策 | 最小行为 |
| --- | --- |
| 重复 | 每天，或每周指定星期；周一至周五仅为快捷选项，不处理节假日/调休 |
| 日期 | 开始日不得早于计划当地今天；结束日可空，含结束当日 |
| 生成范围 | 仅生成当地今天，不提前生成未来任务；任务列表未来日期不显示虚拟任务 |
| 计划修改 | 从当地次日生效，不回写任何已生成任务；界面不用含糊的“修改全部” |
| 单次修改 | 走既有任务编辑/取消接口，保留最终 owner/版本 CAS；不影响计划 |
| 停止 | 立即禁止新增实例，永久停止本计划；已有实例原样保留，需要时逐条取消，不自动清空今日待办 |
| 停机 | 恢复后只补今天，过去未生成的执行日记录为生成缺口，不自动补为逾期/未完成，不补发星 |
| 材料 | 首版计划只包含文字及目标参数，不复制附件、清单、来源链接；每日任务仍可按既有能力单独加材料和提交作品 |
| 时区 | 创建时从家庭读取并固定 IANA 时区；计划不可改时区，家庭后续改时区不静默移动既有计划。界面显示计划时区；需换时区时停止后新建 |

无结束日期不代表一次生成无限任务。暂不做暂停/恢复、节假日日历、次数补签、跨日时段、通知推送、连续打卡奖励、通用调度/恢复框架。停机缺口需要家长补记时，沿用手工单次任务，不自动关联或反向填补计划历史。
计划固定时区与家庭新时区可能不同；提示须明确，今日计划/周报沿用既有任务 dueDate 规则，不将计划改时区作为隐式迁移。

## 3. 持久化与权限

新增 homework 自有 `RecurringTaskPlan`：familyId、childId、createdByParentId、timezone、startDate、status(active/stopped)、version、stoppedAt/stoppedByParentId；currentRevision 和至多一份 pendingRevision。
revision 包含 revisionNumber、effectiveFrom、完整 template、schedule、endDate；首次为 1，后续取本次计划 version。明日修改尚未生效时，再次修改覆盖整份 pendingRevision，但原命令日志保留每次成功快照；到期才提升为 currentRevision。
计划 DTO 的版本是管理 CAS，不等于单次任务 completionVersion。

template 白名单：dimension、area、subject、title、taskType、description、estimatedMinutes、targetAmount、unit、priority；类型及长度/枚举沿用现有创建校验，不接收 actor、状态、奖励、媒体、清单、sourceTaskId/sourceMistakeId。
生成时显式构造任务，不 spread 整份计划或复制完成状态。实例新增只读 recurringPlanId、occurrenceDate、planRevision；dueDate 初值为 occurrenceDate。
允许家长依现有接口改单次 dueDate，但 occurrenceDate 永不变，不重新生成原日期；它是生成身份，不是可编辑截止日。

唯一索引：GrowthTask 上 `(recurringPlanId, occurrenceDate)`，仅对合法 ObjectId/string 两字段的重复任务生效；普通任务无这两个字段。不能将 status 放入唯一键，取消/归档也持续占用原日期。启动前验证索引真实可用，不做历史任务自动迁移。

管理命令新增小型 `RecurringTaskPlanCommand`，仅本功能使用，不建通用 operation 平台：
唯一 `(familyId, actorId, operationId)`，保存 schemaVersion=1、childId、动作/目标、requestDigest、state 和终态时间。state 仅有 succeeded/aborted，不新增通用排队或远端恢复平台。
succeeded 额外保存完整规范命令正文、服务端生效日期、planId、原成功HTTP状态及快照，与所有计划/实例修改同事务提交。不能仅保存摘要后声称能返回原正文。
aborted 为不可变拒绝墓碑，只保存原最小身份/摘要和中止时间，不保存未知正文、不创建/修改计划或实例。成功和中止共用上述唯一键，无 TTL 自动删除记录。
相同命令同正文重放历史结果；相同 ID 异动作/目标/正文冲突。不同 actor 同 UUID 相互独立；两个独立创建命令可创建同名计划，UI 防双击但不按标题猜测合并。匹配 aborted 的原业务写永远拒绝，不能覆盖墓碑或复用该 UUID。

每次管理、重放和查询实时校验家长成员资格及孩子归属，撤权后不得因旧命令存在返回私有快照。孩子只能读/完成自己实例，无计划管理权。
扫描器每次事务核对家庭/孩子仍有效且归属一致；创建家长退出家庭不会自动删除共管家庭计划，创建审计不伪造为当前在线家长。不跨服务写数据库，复用 homework 既有授权读取方式。

## 4. 生成、去重与停机

创建计划事务若今天命中，原子生成今天实例；否则仅存计划。之后服务启动成功及每 60 秒触发一次串行扫描，不在 import 或 GET 中启动/写入，不要求孩子登录才生成。时间间隔不是 SLA；失败要可见而非假成功。
扫描按持久公平分页每页最多 50 计划、一次只执行一个计划事务；批次串行并让出事件循环，不引入队列、Redis或新服务。游标推进失败不得跳过该页；单计划失败记为本轮失败并继续其他计划，下一轮重新尝试，不永久饿死后续计划。多副本无需全局锁，但必须靠同计划事务写冲突与唯一索引去重。未遍历完不把扫描标为健康完成。

每个计划持久保存 lastEvaluatedDate、generationFence、最近成功/失败状态及 skippedRange 摘要（起止、匹配执行日数）；仅保存日期/错误码，不记录孩子内容。初始水位 startDate 前一天。首次开始日在未来时不提前推进水位。
计划事务流程：
1. 重新读取计划、归属及服务端时钟。拒绝无效时区或时钟回退到水位之前，不删除/重建历史。
2. 当明日版本已到期，使用其生效日起的规则；停机跨版本时缺口按旧/新规则分段计算，完成后才提升并清 pendingRevision。
3. 对水位之后、今天之前且在计划起止范围内的匹配日只累记缺口，不创建任务。重复扫描不得重复计数；计划结束后仍需最终扫至结束日一次，才退出候选集合。按整周及不足一周的余数计算匹配日数，不遍历多年日期或写逐日缺口记录。
4. 今天匹配且未停止时，用唯一生成身份插入实例；已存在时只读取，不覆盖其材料、任务状态、日期或审计；不匹配则仅推进已评估水位。
5. 对计划 generationFence 做条件写，与实例插入/水位/缺口同一 Mongo 事务提交。修改、停止和扫描都写同一计划，不能只读计划后无栅栏插入。

跨午夜必须在最终写前再采样；日期与事务开头不同则回滚重算，不把昨天提交成今天。重算次数有界，持续不稳返回/记录可重试失败。事务提交未知时按原唯一身份查询/重试，不能新建 taskId 当成另一条发生。
唯一键冲突仅在核对已存在行完整生成身份/家庭/孩子一致后视为已生成，其他异常均失败；不吞掉所有 duplicate key。

修改与停止事务也必须先折叠到期版本、记录截止今天之前的未评估缺口，再变更规则，以免丢失停机历史。它们不补旧任务。
停止不依赖补生成成功，也不为停止创建今天任务；并发扫描若先提交，该实例保留；停止若先提交，扫描重试见 stopped 必须零插入。响应和 UI 明确“已生成任务保留”，不承诺撤销先于停止成功发布的实例。
计划列表提供 generationHealth 与缺口提示；生成缺口不计入既有任务完成率分母，也不能被解释为执行率100%。周报不改统计口径，计划页单独说明缺口。

## 5. 修改、停止和未知结果

计划修改必须 expectedVersion；服务端以本次事务日期计算 effectiveFrom=明天。startDate/childId/timezone 不可改，endDate 可空或不早于 max(startDate,明天)。已结束计划不可延长/恢复，停止或新建；停止已结束计划允许，用于明确终止管理。
旧预览/共管竞争返回版本冲突，用户重新查看后再决定，不自动套用新版本。修改不改今天任何实例；需要改今天时使用“仅这一次”。
停止必须 expectedVersion；已停止的原 operationId 重放保留首次审计；新命令针对已停止计划返回状态冲突，不改变停止人/时间。
命令全部仅本地事务，不增加远端 operation。503/断网不得推测失败或换 UUID；前端保留原命令和禁重复发送状态，显式原命令重试/查询。跨午夜重放命中已提交日志时返回原生效日期，不顺延；未提交的命令第一次真正成功时用当日服务端日期。

### 5.1 退出保留的最小标记

有效意图首次发送前，将 `{schemaVersion:1,familyId,actorId,childId,operationId,action,targetPlanId,requestDigest}` 写入本功能 localStorage 专用键并回读相等后，才允许 HTTP 写入；create 的 targetPlanId 为 null，patch/stop 为目标计划 ID。摘要算法及目标绑定见 API §4。不保存标题、描述、目标参数、PIN、Token、Cookie或完整正文；该标记不是授权凭据，也不记录日志。
键包含 schemaVersion/familyId/actorId/childId/operationId，值与键必须一致；持久写入失败、损坏、版本未知或身份不一致时零业务 POST/PATCH，不降级成内存标记后发送。正文仅留当前会话内的原命令缓存。
主动退出/切换身份清除正文、私有视图和已载入回执，但保留上述最小标记，不被通用命令清理误删；这是本次明示的清理例外。采用已有请求 epoch/会话隔离方式，不改其他功能的退出策略。
仅同一 actor 重新认证且 family/child 实时授权成功后，才加载其标记并逐个只读查询；其他家长（包括共管）和孩子不能看到或处理它。403/迟到401清当前私有视图但不把未知标记当成功移除；撤权期间禁止恢复，保留隔离标记，不承诺无权限时解除。
当前 actor/child 有未决标记时，阻止其发起新的计划创建/修改/停止命令，仅允许查询、正文仍在且摘要一致的原ID重试、或显式终止原命令。其他孩子/actor 的正常工作不被该标记阻塞。多标签页在写前及 storage/focus 接续时重新核对标记；独立新意图不是跨标签页自动去重对象。
清除浏览器站点存储会丢失本地保护，不能承诺此时恢复尚未到达服务器的请求；UI 不推荐清缓存解除未知状态。服务端成功命令索引仍可发现已提交结果，但不能冒充在途列表。

### 5.2 重登恢复与安全解除

GET 为 succeeded 时，验证回执的完整 scope、原 operationId、动作/目标及摘要，再读取当前计划；历史成功快照不能覆盖最新状态。GET 为 not_found 时只说明当前未查到终态，仍保留标记；不能因列表为空、等待时长、网络恢复或本地 AbortController 而换 UUID。
正文已因退出丢失且结果未定时，不凭摘要重建正文、不自动重发。用户可继续只读查询，或显式选择“终止这次未确定的提交”；这不是停止计划，也不撤销已成功的操作。
新增仅本功能的 abort 入口，接受最小标记（认证身份仍取服务端）：在同一唯一键上，若 succeeded 已提交则原样返回成功；若 aborted 已提交则原样返回中止；若尚无记录，则事务插入 aborted 墓碑。身份/动作/目标/摘要不匹配一律冲突，不能返回另一个意图的成功或中止结果。
业务写与成功记录必须同事务，事务开始检查终态且最终成功记录排他插入，不得 upsert 覆盖 aborted。abort 与在途业务写竞争：业务事务先提交则 abort 只能返回 succeeded；abort 先提交则原业务事务因唯一键/写冲突整体回滚，重读 aborted 后拒绝。不能先提交计划再补写命令日志。
只有取得并核验 succeeded 或 aborted 持久终态，才条件删除完全匹配的本地标记。原业务201/200仍沿用原响应形状，没有完整命令identity，因此也先GET命令终态再清标记；这次GET失败可提示业务响应已成功但结果核对待完成，不能自动再次发新命令。原身份 epoch 已失效的迟到响应不得清标记或恢复私有UI；同身份稍后重新查询再解除。not_found、503、403、摘要冲突及 abort 丢响应均保锁。一个旧终态回执不能删除新 operationId 的标记。
aborted 的含义是“该原命令未产生已提交业务变更，且以后也不能提交”，不是根据观察猜测“当时没请求”。确定未发送/回滚但标记仍在的命令也走同一墓碑路径解除，避免永远等待不存在的成功记录；取得终态后才允许用户另建新意图、新 UUID，绝不自动新建。
发出过请求后，即使收到校验或版本冲突，也不能凭这一份响应证明不存在另一在途重试；需要放弃意图时同样终态化后解除。本地校验应在写标记前完成，未开始发送、尚未持久化标记的普通表单错误不受此限制。
abort 超时/提交未知仍使用原 operationId 和同一最小正文重试/查询，不生成第二个 abort 命令 ID。命令功能关闭时保留 GET，abort 也停止写入并保锁，等待能力恢复；此限制不取消任何已有任务。

## 6. 单次闭环与奖励

生成实例初始 pending、完成版本按既有默认、starAwardState=not_applicable；不生成完成作品、不调用 progress。
编辑/取消、材料准备、完成和确认完全复用正式服务及 owner/阶段/版本互斥，不能为重复任务走旁路。计划修改/停止不读取或写奖励，不修改确认审计。
同一实例重复确认/共管接续只发一次星；不同日期是不同 taskId，各自首次确认可各发一颗。已取消实例不重新生成；已归档实例仍可用作去重，不删账本。未知完成结果仍按原完成 operationId 恢复，不使用计划命令替代。

## 7. 接入、失败与回退

新增默认关闭功能开关 `RECURRING_TASKS_ENABLED=false`，管理写入与生成同开关；关闭时计划读/原命令结果查询可用，实例旧业务仍工作，管理写返回明确关闭错误。不开启计划能力不改变旧 repeatRule 拒绝。
启用需事务能力及唯一索引就绪，使用既有服务启动预检，不跳过上传/媒体/凭据等原检查。关闭扫描器不清记录，不宣称按时生成；重新启用遵循只补今天规则。
扫描器停止时停止新批次并等待本轮事务有界收尾，未知提交保留证据；导入模块和单测不得自动监听或扫描。运行错误仅记录脱敏代码及生成健康，不自动放宽规则。
回退是关闭新能力并保留模型/索引及生成字段兼容，不回滚到会丢字段或忽略 aborted 墓碑的旧写入路径；不能删除实例、去重/命令记录或已发星流水。
首批仅本地核心实现及合成测试，HTTP/页面/服务定时接线尚未启用。实现必须先通过对应合成事务/HTTP/浏览器测试再申请交付，不影响当前真人入口。

## 8. 状态边界

这是新增功能设计候选，不改写 PRD/API 中当前已实现的单次任务历史约定。审批通过后实施时再追加正式能力状态，不把设计视为接口已上线。
